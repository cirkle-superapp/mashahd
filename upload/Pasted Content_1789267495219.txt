# 10. TURSO WRITE ECONOMICS

Because database writes are a resource, minimize write amplification.

Do NOT write:

```text
one database record per media segment
one database record per P2P packet
one database record per heartbeat
```

```text

→ batch
→ aggregate
→ write periodically
```

Peer presence should primarily live in ephemeral memory/Redis-compatible state, not permanent database rows.

Prefer:

```text
local cache
→ useful peer
→ local edge
→ trusted seed
→ WebTransport edge
→ R2
```

subject to deadline and reliability.

---

# 78. COST-AWARE ROUTING

Relative cost model:

```text
Local cache       ≈ 0
P2P               ≈ minimal operator cost
Self-hosted edge  ≈ low
Trusted seed      ≈ low
WebTransport edge ≈ controlled
R2                ≈ storage/operations cost, zero Internet egress
Filebase          ≈ archive/backup tier
```

Do NOT assume R2 is completely free beyond its allowances; current R2 pricing charges for storage and operations after included free allowances.

---

# 79. DATABASE COST AWARENESS

Do not create large telemetry workloads in Turso.

Aggregate:

```text
playback telemetry
peer stats
heat
scheduler observations
```

before persistence.

The current Turso free plan has generous read capacity but finite storage/write allowances, so MASHAHD must keep the database as a control-plane database rather than a high-frequency event sink.
